## 1. Сводка обязательных требований к второй главе

### Из чек-листа 2026 (документ нормоконтроля, **приоритет**):

| Объект | Требование |
|---|---|
| Структура работы | **ТРИ раздела** + выводы по каждому разделу |
| Подразделы в каждом разделе | **не менее 2, не более 4** |
| Объём раздела | **20–25 страниц** |
| Объём подраздела | **не менее 3 страниц** |
| Выводы | после каждого подраздела (кратко, без спец. оформления) + обобщённые в конце раздела (специально оформляются) |
| Аннотация | на **русском И английском** языках |
| Список литературы | не менее **20** источников, по мере появления ссылок в тексте, актуальная литература 3–5 последних лет |
| Антиплагиат | не менее **75%** оригинальности |
| Ссылки на источники | `[N]` в квадратных скобках, точка после скобок |
| Нумерация рисунков/таблиц | сквозная по всему тексту, арабские цифры, формат «Таблица 1», «Рисунок 1», источник `[1]` после рисунка/таблицы |
| Шрифт | Times New Roman, 12 или 14 pt; абзац 1.25 см; интервал 1.5; поля 30/15/20/20 мм |
| Заголовки | без точки в конце, переносы не допускаются, разделы — с новой страницы |

### Из методички 2024:

| Объект | Требование |
|---|---|
| Объём | 60–100 страниц основной части (без приложений) |
| Структура (Приложение Е, шаблон аннотации) | Допускается **«два раздела»** — внутреннее противоречие с чек-листом |
| Стиль | Безличный, без первого лица |
| Критерии оценки «отлично» (Приложение З) | Обязательно «анализ предлагаемых способов реализации поставленных задач; **оценка экономической, экологической, технической, социальной эффективности их внедрения**» |
| Материалы к защите | Включают «**отзыв от организации, где были внедрены результаты**» (аналог акта внедрения) |
| Презентация защиты | Обязательны слайды «описание программного обеспечения», «основные результаты», «пути внедрения результатов» |

### Противоречие документов и его разрешение

Чек-лист 2026 жёстко требует трёх разделов; методичка 2024 в Приложении Е (шаблон аннотации) описывает двухразделовую структуру. Чек-лист — позднее по дате и является документом нормоконтроля. **Приоритет — у чек-листа.**

При этом во **введении ВКР заявлена структура из двух глав** (строки 34–38 `введение.md`): «Выпускная квалификационная работа состоит из введения, **двух глав**, заключения...». Это нужно обсудить с научным руководителем: либо изменить структуру под чек-лист (3 раздела), либо получить согласие руководителя на 2 раздела со ссылкой на Приложение Е методички.

## 3. Дополнительные проблемы по всей работе

### 3.1. Глава 1 уже нарушает лимит подразделов

В написанной главе 1 — **семь подразделов** (1.1–1.7), при максимуме 4 по чек-листу. Это уже свершившийся факт; решения:

**Вариант (а)** — оставить как есть и получить замечание нормоконтроля, либо аргументировать руководителю.

**Вариант (б)** — объединить подразделы при сохранении нумерации внутреннего деления через 3-й уровень (1.1, 1.2, 1.3, 1.4), а нынешние 1.1–1.7 переразбить как 1.1.1–1.4.x. Это переразбивка только заголовков, текст не переписывается.

Возможная переразбивка главы 1 в 4 подразделов:
- 1.1 Анализ предметной области (= текущий 1.1)
- 1.2 Сравнительный анализ существующих решений (= текущий 1.2)
- 1.3 Проектирование архитектуры и технологического стека (объединение 1.3 + 1.4 + 1.5 + 1.6 как 1.3.1–1.3.4)
- 1.4 Стратегия развёртывания (= текущий 1.7)

Решение оставляется научному руководителю. Решение по главе 2 принимается ниже, исходя из факта несоответствия плана требованиям.

### 3.2. Введение заявляет 2 главы

Введение содержит фразу «состоит из введения, двух глав». При переходе на трёхразделовую структуру эту фразу нужно будет править.

### 3.3. Отсутствуют артефакты, ожидаемые методичкой

- Аннотация на английском — обязательна по чек-листу.
- Технико-экономическая оценка — обязательна для критерия «отлично» по методичке.
- Приложение со скриншотами интерфейса — пример в чек-листе («ПРИЛОЖЕНИЕ Д — Макеты интерфейсов веб-приложения») фактически делает его рекомендуемым для веб-ВКР.
- Графическое приложение / схемы — упомянуты в Приложении В методички.

## 4. Переработанный план 2-й главы

Предлагается **два варианта**, в зависимости от решения по структуре работы (2 или 3 раздела).

### Вариант I (двухразделовая структура — сохраняет заявку Введения)

Глава 1 — теория и проектирование, Глава 2 — реализация, тестирование и оценка. План 2-й главы сокращается с 5 до 4 подразделов:

| Подраздел | Объём | Содержание |
|---|---|---|
| **2.1 Реализация серверной части и финансовой модели** | 8–10 стр. | Структура проекта, auth-service (JWT RS256, token-family rotation), api-gateway, groups-service, expenses-service (split engine, balance engine, greedy-минимизация — с привязкой к §1.6), outbox-worker, notify-service. **Выводы по подразделу.** |
| **2.2 Реализация клиентской части и инфраструктуры развёртывания** | 8–10 стр. | React SPA: маршрутизация, TanStack Query + Zustand, основные пользовательские сценарии со скриншотами. Docker Compose dev/prod, Nginx (rate-limit, TLS), certbot, systemd-юниты, бэкап PostgreSQL. **Выводы по подразделу.** |
| **2.3 Тестирование и верификация инвариантов** | 5–7 стр. | Стратегия (unit + integration + smoke), property-based тестирование финансовых инвариантов (sum=0, граница N−1, корректность округления), тестирование security (token rotation, cookie-параметры), результаты тестирования с таблицей, метрики покрытия. **Выводы по подразделу.** |
| **2.4 Оценка результатов и опытная эксплуатация** | 4–6 стр. | Таблица F1–F8/NF1–NF6 → статус (реализовано/частично/v2), технико-экономическая оценка (трудозатраты, стоимость VPS-инфраструктуры, сравнение с лицензионной стоимостью Splitwise Pro / Tricount Premium), ограничения MVP, направления развития. **Выводы по подразделу.** |
| **Обобщённые выводы по разделу 2** | 0.5–1 стр. | Специально оформленные выводы по 2–4 содержательным результатам главы и связь с заключением ВКР. |
| **Итого** | **25–32 стр.** | На верхней границе лимита раздела 25 стр. может потребоваться сокращение. |

### Вариант II (трёхразделовая структура — соответствует чек-листу)

Текущая «глава 1» переразбивается, чтобы освободить место под третий раздел. Возможная разбивка работы:

| Раздел | Объём | Что входит |
|---|---|---|
| **Раздел 1. Анализ предметной области и обоснование разработки** | 22–25 стр. | 1.1 Предметная область (текущие 1.1+1.2), 1.2 Обоснование архитектуры и стека (текущий 1.3), 1.3 Проектирование БД и API (текущие 1.5+1.6), 1.4 Стратегия развёртывания (текущий 1.7) |
| **Раздел 2. Реализация веб-приложения** | 22–25 стр. | 2.1 Реализация серверной части и финансовой модели, 2.2 Реализация клиентской части, 2.3 Реализация инфраструктуры развёртывания, 2.4 Реализация подсистемы безопасности (JWT, token rotation, rate-limit, TLS) |
| **Раздел 3. Тестирование, оценка и опытная эксплуатация** | 20–22 стр. | 3.1 Стратегия и методика тестирования, 3.2 Результаты тестирования и верификация финансовых инвариантов, 3.3 Технико-экономическая оценка, 3.4 Опытная эксплуатация и ограничения MVP |

**Существенное:** перенос текущих §1.4 «Проектирование архитектуры» в раздел 2 как «Реализация архитектуры» требует существенной переписки уже написанного текста главы 1, поскольку «проектирование» и «реализация» — разные жанры. Поэтому Вариант II — это **значительная переделка**, а не косметическая перенумерация.

## 5. Рекомендация

**Рекомендуется Вариант I** (сохранить двухразделовую структуру, как заявлено во Введении):

1. **Минимальное переделывание уже написанного текста.** Глава 1 нуждается только в переразбивке заголовков 1.1–1.7 на 1.1–1.4 с подуровнем 1.x.y (косметика), а не в переписке.
2. **Опора на Приложение Е методички 2024**, которое явно описывает двухразделовую структуру для ВКР: «Пояснительная записка содержит введение, два раздела и заключение». Это формальное обоснование при возможном замечании нормоконтроля.
3. **Согласование с научным руководителем** — необходимо. Перед началом написания главы 2 показать руководителю этот файл и зафиксировать выбор структуры.

### Что обязательно сделать перед началом написания главы 2

1. **Принять переработанный план**: 4 подраздела (2.1, 2.2, 2.3, 2.4) + обобщённые выводы.
2. **Запланировать выводы** в каждом подразделе (1–2 абзаца в конце).
3. **Запланировать технико-экономическую оценку** в §2.4 как обязательный блок (критерий «отлично»).
4. **Запланировать приложения** для главы 2: скриншоты UI (Приложение Д), фрагменты кода (Приложение В), результаты тестирования (Приложение Г), схема развёртывания (Приложение Б, расширение текущей).

### Что нужно сделать по работе в целом (вне главы 2)

5. **Аннотация на английском** (ANNOTATION). Краткая, до 500 символов.
6. **Переразбить главу 1** на 4 подраздела (Вариант (б) из §3.1) после согласования с руководителем.
7. **Поправить введение**: фраза «двух глав» оставляется (соответствует Варианту I), но фраза о структуре главы 1 («рассматриваются... анализ... сравнительный анализ... обоснование... проектирование... базы данных, API... стратегия развёртывания») остаётся актуальной.
8. **Проверить шрифт и поля документа** перед сдачей: Times New Roman 14 pt (или 12 pt, чек-лист допускает оба), интервал 1.5, поля 30/15/20/20 мм, абзац 1.25 см.
9. **Проверить нумерацию рисунков, таблиц, формул** — арабская сквозная по всему тексту.
10. **Подтвердить минимум 20 источников** в `bibliography.md` (сейчас 45 — норм, превышение допустимо).
11. **Перед сдачей проверить антиплагиат** (≥75% оригинальности).

## 7. Открытые вопросы для научного руководителя

1. **Структура работы:** оставлять 2 главы (как во Введении) или перейти на 3 раздела согласно чек-листу?
2. **Подразделы главы 1:** переразбить с 7 на 4 (по варианту (б) §3.1) или оставить как есть?
3. **Технико-экономическая оценка:** в каком объёме включать в §2.4 (полстраницы краткой оценки или 1–2 страницы с таблицей)?
4. **Опытная эксплуатация / отзыв организации:** возможно ли получить отзыв от тестовых пользователей или команды-партнёра проекта? Если да — это даст плюс к оценке «отлично» по критерию «эффективности внедрения».
5. **Английская аннотация:** требуется ли отдельный перевод текста ВКР или достаточно аннотации на английском?
6. **Антиплагиат:** на какой системе кафедра проверяет работу (антиплагиат.вуз / антиплагиат.ру)? Это влияет на технику обеспечения 75% оригинальности.
