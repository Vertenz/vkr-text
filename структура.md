## Глава 1. Теоретические основы и проектирование системы (~35–40 стр.)

### 1.1 Анализ предметной области (~5 стр.) ✅ написано → `1_1_анализ_предметной_области.md`
- Понятие совместных расходов и групповых финансовых расчётов
- Типичные сценарии использования (путешествия, съёмное жильё, корпоративы)
- Ключевые операции: добавление траты, распределение суммы, расчёт балансов, погашение долгов
- Формализация финансовой модели: участники, траты, доли, баланс, взаиморасчёты

### 1.2 Обзор и сравнительный анализ существующих решений (~6–7 стр.) ✅ написано → `1_2_сравнительный_анализ.md`
- Splitwise, Tricount, Honestlly, отечественные аналоги
- Сравнительная таблица по критериям: функциональность, открытость, локализация, стоимость
- Вывод: обоснование необходимости собственной разработки

### 1.3 Выбор архитектурного подхода и технологического стека (~6–7 стр.) ✅ написано → `1_3_выбор_архитектуры_и_стека.md`
- Монолит vs. микросервисы — выбор и обоснование
- Обоснование выбора FastAPI, Nuxt 4, PostgreSQL, RabbitMQ, Nginx
- Сравнение с альтернативами (Django/Express, Vue SPA vs SSR, MySQL, Kafka)
- Паттерны: Outbox pattern, Repository, Event-driven

### 1.4 Проектирование архитектуры системы (~7–8 стр.) ✅ написано → `1_4_проектирование_архитектуры.md`
- Компонентная архитектура (frontend, backend, БД, брокер, proxy)
- Диаграмма компонентов / схема взаимодействия узлов (Рисунок X)
- Безопасность: JWT RS256, схема аутентификации
- Событийная архитектура: Outbox → RabbitMQ → уведомления

### 1.5 Проектирование базы данных (~5–6 стр.) ✅ написано → `1_5_проектирование_бд.md`
- Схемы PostgreSQL: auth, groups, expenses, notify
- ER-диаграмма (Рисунок X)
- Ключевые таблицы, связи, инварианты данных
- Стратегия миграций (Alembic)

### 1.6 Проектирование API и финансовой модели (~6–7 стр.) ✅ написано → `1_6_проектирование_api.md`
- REST API, OpenAPI-спецификация, основные эндпоинты
- Финансовая модель: алгоритм split engine (поровну и в произвольных долях)
- Алгоритм минимизации взаиморасчётов (упрощение долгового графа)
- Примеры расчётов с иллюстрацией

### 1.7 Стратегия развёртывания (~2–3 стр.) ✅ написано → `1_7_стратегия_развёртывания.md`
- Целевая платформа: VPS под управлением Ubuntu Server LTS, обоснование выбора
- Сетевая модель: единая публичная точка входа, многоуровневая защита периметра
- TLS-терминация и автоматизация сертификатов Let's Encrypt по протоколу ACME
- Безопасность хост-системы: непривилегированный пользователь, SSH-ключи
- Управление миграциями и порядок запуска (schema-guard)
- Эксплуатационные принципы: автозапуск, резервное копирование, ротация журналов

## Глава 2. Реализация и тестирование веб-приложения (~35–40 стр.)

### 2.1 Реализация backend-сервисов (~10–12 стр.)
- Структура проекта FastAPI, слои приложения
- Реализация аутентификации и авторизации (JWT RS256, refresh tokens)
- Реализация доменных сервисов: группы, расходы, балансы, settle up
- Реализация Outbox + RabbitMQ pipeline для уведомлений
- Работа с PostgreSQL через SQLAlchemy + Alembic

### 2.2 Реализация frontend-приложения (~8–10 стр.)
- Структура Nuxt 4 приложения, SSR, Pinia store
- Основные страницы и компоненты: группы, расходы, балансы, история
- Взаимодействие с API, обработка ошибок
- Ключевые UX-решения (Рисунки с экранами)

### 2.3 Инфраструктура и развёртывание (~5–6 стр.)
- Docker Compose: сервисы, сети, volumes
- Nginx как reverse proxy: конфигурация, маршрутизация
- Переменные окружения и конфигурация (.env)
- Процедура развёртывания на VPS

### 2.4 Тестирование системы (~7–8 стр.)
- Стратегия тестирования: unit и интеграционные тесты
- Тестирование финансовой модели (split engine, расчёт балансов)
- Quality gate: покрытие, линтеры, автоматизация
- Результаты тестирования (таблица)

### 2.5 Оценка результатов разработки (~3–4 стр.)
- Соответствие системы заявленным функциональным требованиям
- Достигнутые характеристики: функциональность, воспроизводимость развёртывания
- Ограничения и направления дальнейшего развития
